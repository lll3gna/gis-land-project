# gis-land-project
# GIS Land Project (Участок VOK-104)

Репозиторий для совместной работы над проектом по обработке геоданных и ГИС участка **VOK-104**. Главная цель текущего спринта — обеспечить бесшовную стыковку скриптов анализа кадастровых данных и обработки снимков с модулями сегментации.

---

## 📂 Структура репозитория

*   `cadastre/` — Скрипты Влада для работы с кадастровыми данными (границы, выписки, кадастровые номера).
*   `imagery/` — Скрипты Влада для предварительной обработки спутниковых и аэрофотоснимков.
*   `segmentation/` — Модули Ксюши по распознаванию и сегментации объектов на снимках.
*   `export/` — Модули Ксюши для экспорта результатов в форматы DXF/PDF.
*   `data/samples/` — Тестовая выборка геоданных и фрагментов снимков для проверки работоспособности кода.
*   `prompts/` — Проверенные промпты и инструкции для Codex.
*   `docs/` — Документация проекта. Единая схема данных находится в актуальном состоянии в файле `docs/data-schema.md`.

---

## 🚀 Как запустить проект

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com
   cd gis-land-project
   ```
2. **Настройте окружение (рекомендуется Python 3.10+):**
   ```bash
   python -m venv venv
   source venv/bin/activate  # Для macOS/Linux
   # или venv\Scripts\activate  # Для Windows
   ```
3. **Установите базовые ГИС-зависимости (при необходимости дополняйте `requirements.txt`):**
   ```bash
   pip install -r requirements.txt
   ```

## 🤖 Правила работы с ИИ-ассистентом Codex

Codex используется как основной инструмент для генерации, оптимизации и рефакторинга кода. Чтобы скрипты Влада и Ксюши стыковались без переделок, соблюдайте следующие правила:

1. **Обязательная сверка со схемой:** Перед отправкой запроса в Codex на написание функций ввода-вывода или обработки, передайте ему содержимое файла `docs/data-schema.md`. Код должен строго использовать согласованные форматы (GeoJSON, WGS 84 / EPSG:4326, наименования классов объектов).
2. **Формирование промптов:**
   * Все сложные или часто используемые промпты сохраняйте в папку `prompts/` в формате `.txt` или `.md`.
   * Явно указывайте Codex среду выполнения (например, *"Напиши функцию на Python с использованием библиотеки GeoPandas..."*).
3. **Логирование изменений:** Если Codex полностью переписал логику функции, добавьте комментарий в код с кратким описанием промпта, который использовался для генерации.

## 🛑 Правило «Никаких ключей в коде» (Безопасность)

**СТРОГО ЗАПРЕЩЕНО** сохранять в файлы кода, пушить в репозиторий или передавать в открытых промптах:
*   API-ключи сторонних геосервисов (Mapbox, Google Earth Engine, Яндекс.Карты и др.).
*   Пароли и доступы к базам данных или локальным ГИС-серверам.
*   Персональные токены доступа GitHub.

**Как делать правильно:**
Все конфиденциальные данные должны храниться локально в файле `.env` в корне проекта (этот файл автоматически игнорируется через `.gitignore`). Доступ к ним в коде осуществляется через библиотеку `python-dotenv`:
```python
import os
from dotenv import load_dotenv

load_dotenv()
API_KEY = os.getenv("GEOPORTAL_API_KEY")
```
