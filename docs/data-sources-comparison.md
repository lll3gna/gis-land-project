# Сравнение источников кадастровых данных и спутниковых снимков

**Спринт:** 2–15 октября  
**Ответственный:** Влад (GIS/геоданные)  
**Дата актуализации:** 06.10.2026

> В таблице ниже разделены два разных сценария: (1) источник данных для внутренней обработки/MVP и (2) картографическая подложка для отображения пользователю. Для платного продукта особенно важно не путать право показывать тайлы в приложении с правом скачивать, кэшировать, перерабатывать и продавать производные данные.

## Критерий MVP

Для земельных участков 6–15 соток (600–1500 м²) нам нужен исходный снимок **не хуже 0,5 м/пиксель**. Sentinel-2 с 10 м/пиксель не подходит для выделения границ/объектов на таком участке и оставляется только как фоновый источник.

Для imagery предпочтителен источник, который позволяет получить исходный/обработанный GeoTIFF или иной растр с понятными правами на коммерческую обработку. Обычная веб-подложка по тайлам не считается автоматически подходящим источником для обучения/сегментации.

### Вывод по кадастру

**Берём НСПД как основной источник публичной кадастровой геометрии и идентификаторов.** Для критических случаев и проверки атрибутов используем официальную выписку ЕГРН/Роскадастр. API-агрегатор можно подключить позже для удобного поиска и снижения количества ручных операций, но он не должен быть источником истины.

Важно: НСПД и публичная кадастровая карта удобны для просмотра и получения публичных пространственных данных, но публичная карта сама по себе не заменяет официальную выписку ЕГРН. Росреестр отдельно указывает, что просмотр ПКК осуществляется без подачи запросов и платы, а выгрузка координат именно в рамках публичной кадастровой карты не предусмотрена. Для производственного обмена используем доступные официальные электронные сервисы/слои НСПД, а не scraping интерфейса.

## 3. Что реально подходит под 0,5 м/пиксель

### Не подходят как основной source

- Sentinel-2 — 10 м.
- Роскосмос: большая часть каталогов имеет 1–60+ м; подходит только конкретная съёмка/аппаратура с нужным GSD.
- Google/Yandex — разрешение по месту непредсказуемо и важнее всего лицензионные ограничения.
- Esri World Imagery — качество часто достаточно хорошее, но это мозаика из разных поставщиков; конкретный GSD и права нужно проверять по metadata/source.
- Mapbox Satellite — около 0,5 м глобально, но commercial extraction/tracing ограничен лицензией.

### Кандидаты для MVP

**1. НСПД + коммерческая ДЗЗ-съёмка / Роскосмос с подходящей лицензией**

Это наиболее чистая архитектура:

```
НСПД
  ↓
кадастровая граница
  ↓
поиск сцены ДЗЗ по bbox/дате/облачности/GSD
  ↓
снимок ≥ нужного качества
  ↓
GeoTIFF/COG
  ↓
segmentation
```

**2. Sentinel-2**

Оставляем бесплатным резервным/фоновым источником. В segmentation его не подаём.

**3. Esri / Mapbox / Yandex / Google**

Используем для визуального QA и ручного сравнения, но не закладываемся на них как на юридически чистый источник обучающих/производственных растров без отдельного договора.

Для таких участков Абрис **не может получить контур из кадастра** — нужен запасной сценарий: пользователь обводит границу на снимке сам или загружает межевой план. Ранее учтённые участки без границ распространены в старых дачных посёлках, поэтому этот сценарий нужен уже в MVP. Доля таких участков среди пилотных — открытый вопрос.

### Результат ручной проверки

- **НСПД/кадастр:** все три участка находятся по кадастровому номеру. Для двух (28236, 28641) в ЕГРН есть координаты границ — их можно использовать как контур. Для третьего (50507:130) границы не установлены, НСПД показывает только точку, поэтому контур из кадастра получить нельзя.
- **Доступ к НСПД:** сайт работает на сертификате Минцифры (нужно установить корневой сертификат) и отвечает «Forbidden» на зарубежные IP, в том числе через VPN. Карта использует проекцию EPSG:3857. 6–7 октября поиск временно не работал («В процессе поиска произошла ошибка»).
- **Sentinel-2:** технически покрывает все три участка, но 10 м/пиксель даёт слишком мало пикселей на участок и не подходит для выделения зданий/границ.
- **Esri/Mapbox/Yandex/Google:** визуально полезны для QA, но качество/дата imagery зависят от конкретного покрытия; фиксировать «0,5 м» только по названию сервиса нельзя.
- **Роскосмос:** подходит для ручного поиска сцен по геометрии, дате, облачности и разрешению; конкретную сцену нужно отбирать по каталогу, а не принимать весь источник целиком как «0,5 м».

> Ограничение проверки: без авторизованных коммерческих аккаунтов и без заказа сцен нельзя честно утверждать, что на каждом из трёх участков **сегодня** доступен коммерчески лицензируемый снимок <0,5 м. Поэтому в MVP считаем подтверждённым именно наличие/характеристики источника и интерфейса доступа, а наличие конкретной сцены <0,5 м проверяем непосредственно перед загрузкой.

## 5. Итоговая рекомендация MVP

### Берём

**Кадастр:**
1. **НСПД** — primary.
2. **ЕГРН/Роскадастр** — official verification/fallback.

**Imagery:**
1. **Роскосмос / коммерчески лицензируемая ДЗЗ-съёмка** — primary candidate, если конкретная сцена удовлетворяет GSD ≤ 0,5 м/пиксель и лицензия разрешает обработку/коммерческое использование.
2. **Другой коммерческий поставщик высокодетальной ДЗЗ** — backup, если Роскосмос не даёт подходящую сцену по цене/дате/облачности.
3. **Sentinel-2** — бесплатный фон/контекст.

### Не берём в production segmentation

Google Satellite, Яндекс Satellite, Mapbox Satellite и бесплатную Esri World Imagery — не потому, что картинки плохие, а потому что **лицензионные условия и/или способ доступа не дают нам достаточно чистого права строить на их основе коммерческий производный растр/датасет**.
